# Contributing

Thanks for helping make the work clearer and more useful. Contributions can be code, research, examples, questions, corrections, or thoughtful disagreement.

## Before opening an issue

1. Search existing issues and notes.
2. Describe the problem or opportunity in concrete terms.
3. Suggest the smallest experiment that could teach us something.
4. Explain how we would evaluate the result.

## Before opening a pull request

- Keep the change focused on one idea.
- Explain what changed and why.
- Link the issue or decision it relates to.
- Add or update documentation when the public record changes.
- Remove secrets and private information.
- Check links and examples locally.

## Branches and commits

Use a short branch name such as `add-feedback-notes` or `fix-roadmap-link`. Write commit messages with a verb; see [`docs/commit-message-pattern.md`](docs/commit-message-pattern.md).

## Pull requests

A good pull request makes review easy. Include:

- the question or problem;
- the change made;
- evidence or verification;
- open questions; and
- the next step, if one is known.

Small, incomplete work is welcome when it is clearly labeled and shared to invite feedback.

## Scope and safety

Do not publish credentials, private correspondence, personal data, or customer information. When in doubt, redact first and ask before sharing.

The [Code of Conduct](CODE_OF_CONDUCT.md) applies to every project discussion.
