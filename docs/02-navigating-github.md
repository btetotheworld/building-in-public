# Decision Log

Public work is easier to follow when decisions include their context. Use this page, or a dated note linked from here, to record choices before memory smooths out the uncertainty.

## What belongs in a decision

1. **Context:** What changed or forced a choice?
2. **Options:** What realistic paths were considered?
3. **Decision:** What are we doing now?
4. **Reason:** What evidence or constraint made it the best current choice?
5. **Revisit trigger:** What would make us change course?

## Current decisions

### Keep the repository lightweight

**Decision:** Prefer plain Markdown and small, reproducible examples while the direction is still forming.

**Reason:** The important output right now is learning and feedback, not infrastructure. A low-cost format makes it easier to publish often.

**Revisit when:** A repeated workflow becomes painful enough that a tool would remove real friction.

### Publish uncertainty with progress

**Decision:** Record questions, failed attempts, and changes of mind alongside successful work.

**Reason:** Readers can give better feedback when they can see the assumptions behind a result.

**Revisit when:** A type of detail creates risk for a person, customer, or private collaborator.

## Decision template

```markdown
## Decision: Short title

Date: YYYY-MM-DD
Status: active | superseded

### Context

### Options considered

### Decision

### Why

### Revisit when
```

Good decisions are allowed to be temporary. Mark the old one as superseded and link to the replacement instead of rewriting history.
