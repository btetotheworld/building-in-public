# Roadmap

The roadmap describes the next learning loop, not a promise that every idea will ship. Priorities can change when evidence changes.

## Now

- Publish a clear project snapshot.
- Run one small experiment with an observable outcome.
- Invite feedback on the assumptions behind it.
- Record what changed because of that feedback.

## Next

- Turn the most useful experiment into a repeatable workflow.
- Add examples that let a reader reproduce the result.
- Define a small set of signals that show whether the work is helping.

## Later

- Package the strongest workflow for other builders.
- Automate only the repetitive parts.
- Review whether the project should remain a notebook, become a tool, or change direction.

## What is not on the roadmap

- Pretending uncertain work is finished.
- Optimizing vanity metrics before there is a useful outcome.
- Adding infrastructure without a demonstrated need.

## How to suggest a next step

Open an issue with:

- the problem or opportunity;
- who it helps;
- the smallest useful experiment;
- how we would know whether it worked; and
- any relevant evidence or references.

See [`CONTRIBUTING.md`](../CONTRIBUTING.md) for the contribution workflow.
