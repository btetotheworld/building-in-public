# Build in Public Cheat Sheet

## Before you start

- What is the smallest useful thing to try?
- What assumption does it test?
- What evidence would change the next decision?
- What can be shared without exposing private information?

## During the work

- Keep the change small enough to explain.
- Record surprises while they are fresh.
- Separate observation from interpretation.
- Save useful artifacts: screenshots, examples, measurements, or links.

## Public update

```markdown
# Update: YYYY-MM-DD

## Shipped

## Learned

## Evidence

## Still uncertain

## Next experiment
```

## Commit and pull request language

Prefer messages that describe the project change:

```text
Add first onboarding experiment
Update notes with user feedback
Fix broken example link
Remove experiment that did not produce evidence
```

## Feedback

When responding to feedback:

1. Restate what you understood.
2. Say whether the evidence changes your view.
3. Explain what you will try next, or why you will not.

## Privacy check

Before publishing, remove secrets, personal contact details, private customer information, and anything shared in confidence. Public does not mean careless.
