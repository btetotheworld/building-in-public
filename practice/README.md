# Public Practice

These exercises turn the principles in [`docs/`](../docs/) into small, visible habits. They are deliberately lightweight: each one should produce an artifact that another person can read, question, or reproduce.

| Exercise | Practice |
| --- | --- |
| [`01-first-commit`](drills/01-first-commit) | Publish a first project snapshot |
| [`02-branching`](drills/02-branching) | Separate an experiment from the stable record |
| [`03-merge-conflict`](drills/03-merge-conflict) | Resolve competing interpretations |
| [`04-open-a-pr`](drills/04-open-a-pr) | Invite review on a small change |
| [`05-staging-and-unstaging`](drills/05-staging-and-unstaging) | Keep a public update focused |
| [`06-undo-a-commit`](drills/06-undo-a-commit) | Correct the record without hiding the lesson |
| [`07-reading-a-real-repo`](drills/07-reading-a-real-repo) | Study how another project communicates |
| [`08-finding-good-first-issues`](drills/08-finding-good-first-issues) | Find useful public problems to explore |
| [`09-syncing-your-fork`](drills/09-syncing-your-fork) | Bring feedback and new context back into your work |
| [`10-writing-a-pr-description`](drills/10-writing-a-pr-description) | Explain a change so others can evaluate it |

Use your own branch for experiments. Share only what is safe to make public, and link the resulting artifact from an issue or update note.
